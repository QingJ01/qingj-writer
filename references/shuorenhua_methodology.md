# 说人话（shuorenhua）方法论

> 来源：[MrGeDiao/shuorenhua](https://github.com/MrGeDiao/shuorenhua)（MIT License）。
> 核心理念是**先保信息，再谈风格**，设计目标是「去模板感、保事实、减表演」，而不是「去专业术语」或「全改成口语」。
> 本文件是该方法论在情酱写作skill中的落地版：术语保持原样，规则按内容创作和改稿两个场景做了适配。
> SKILL.md 里的「信息保真」节和「模式D」是速查版，本文件是细则。

---

## 核心保留原则

任何改写都不能：

1. **新增事实**（不编数据、不编引语、不编案例细节，尤其不编第一人称的体感和经历）
2. **删核心事实**（不为行文顺畅丢信息点）
3. **改变责任主体**（这件事是谁做的、这句话是谁说的、这个立场是谁的，全程不许换）

**必保项（保护片段）**：

- 数字、数据、日期、时间线
- 人名、产品名、版本号、机构名
- 引语原文（一个字不改；引语内部就算有被禁句式也照抄，动了就是失真）
- 来源和归因（谁说的、哪份材料来的）
- 命令、代码、路径、报错、接口名、参数（照抄，不做任何润色）
- 复盘/事故报告用语（postmortem 的定责表述不许软化）

## 六步执行流程（改稿场景按此顺序，不跳步）

1. **场景判定** — 这段文字是什么：聊天回复 / 状态同步 / 文档 / 公开发布的文章
2. **保护片段** — 按上面的必保项清单把稿子里的硬信息圈出来
3. **问题定档** — 判断命中的问题强度（Tier 1/2/3，见下）
4. **改写档位** — 确定改写力度（minimal / standard / aggressive）
5. **作用域选择** — 确定删改权限（structural / bounded / in-place）
6. **保真回读 + 残余审计** — 两遍回读，先保事实，再查余味

## 问题分级（Tier）

### Tier 1：见一处修一处，零容忍（13个问题族）

1. **开场套话**：值得注意的是、众所周知、在当今社会、随着…不断发展 → 直接删，或换成具体信息
2. **渲染性强调**：深刻影响、至关重要、前所未有、意义非凡 → 改成具体数据，或删掉让内容自己说话
3. **商业/互联网黑话**：赋能、打造、闭环、抓手、痛点、底层逻辑、降本增效 → 换成通俗动词，帮、做、问题、原因
4. **工程师腔/调试腔**（写给大众的内容里）：核心逻辑、一句话总结、根因、兜住、落盘、拆解一下 → 换成具体动作；真技术语境、有实际指标时保留
5. **庸医问诊腔**：抠出来、揪出来、拽出来 → 改成"找出来""定位"
6. **暴力动作腔**：补一刀、狠狠干、更狠、拍脑门 → 换温和动词，删气势渲染
7. **自媒体AI腔**：保姆级、硬核、干货、避坑、一文读懂、绝绝子 → 删掉或改成平实说法
8. **洞见感拔高**：真正的X不是…而是…、不仅仅…更是… → 删拔高骨架，保留事实判断
9. **过渡废话**：综上所述、换句话说、简而言之、某种程度上 → 直接删
10. **正能量收尾**：未来可期、让我们拭目以待、与其…不如 → 删掉，说完就结束
11. **无源权威**：研究表明、数据显示、专家指出（处理方式见「无源引用」节）
12. **谄媚/元评论**：好问题！、希望这对你有帮助、你问到了核心、过度共情式夸奖 → 删掉，直接说事
13. **AI主动出击腔**：我立马开始、要不要我帮你… → 删掉

**翻译腔**单列：被动语态堆砌、超长定语、"基于…""通过…来实现" → 改主动句、拆短句。

### Tier 2：单独出现放行，聚集触发

同一段里出现 2-3 个以上才改：

- 高频连接词（此外、然而、同时、与此同时、事实上）
- 修饰词堆砌（显著、有效、全面、积极、持续、进一步）
- 单音节命令词连用（补、接、核、进、顺、落）
- 重复的姿态词（同段反复"我觉得""说实话"，口语词组堆太密也是一种AI味）

### Tier 3：全文密度过高才处理

- "重要""关键""创新""优化""推动""其实"这类日常高频词，只在通篇密度明显过高时替换**一部分**
- 禁止机械同义词替换：同一个东西就用同一个词，为了避重复刻意换词本身就是AI痕迹

## 结构反模式（20类）

词是表层，结构是骨架。逐类对照（与 `humanizer_zh.md` 有重叠的按两边一致处理）：

| # | 反模式 | 识别特征 | 改法 |
|---|--------|---------|------|
| 1 | 二元对比假戏剧 | "不是X，而是Y"制造虚假顿悟 | 直接陈述，去对立框架 |
| 2 | 否定式列举 | 先说"不是什么"再说"是什么" | 正向陈述 |
| 3 | 戏剧化碎句 | 用单词短语独立成句造势 | 还原成完整陈述句 |
| 4 | 反问式铺垫 | "如果我告诉你…"吊胃口 | 直接给观点和数据 |
| 5 | 虚假主语 | "赋能""助力""驱动"当主语 | 换具体主体和动词 |
| 6 | 被动语态堆砌 | 连续被动句隐藏执行者 | 改主动，写明谁做的 |
| 7 | 三件套列举 | "创新、协作、卓越"式三项组合 | 两项或四项更自然 |
| 8 | 机械递进 | "首先…其次…最后…" | 自然转场承接 |
| 9 | 设问句开头连用 | 段段用问句起手 | 改直陈句 |
| 10 | 总结式收尾 | "综上所述"重复已说内容 | 直接删 |
| 11 | 对称填充 | 为对仗硬凑、无信息增量 | 删冗余项 |
| 12 | 无源引用 | "研究表明"无出处 | 补时间机构数字，或删 |
| 13 | 加粗滥用 | 机械加粗制造假层次 | 删过度加粗 |
| 14 | 分条列点强迫症 | 简单内容也列1.2.3 | 改自然段落 |
| 15 | 正能量收尾强迫症 | 最后必加鸡汤展望 | 说完就结束 |
| 16 | 假口语化/硬凹网感 | 生硬堆砌"绝绝子""谁懂啊" | 用自然口语，删批量网络用语 |
| 17 | 调试腔叙事 | "兜住""落盘""根因"泛化到日常 | 回归日常表达 |
| 18 | 句长均匀 | 每句长度差不多，读感平板 | 长短句交替 |
| 19 | 价值拔高骨架 | "不仅仅是…更是…" | 直陈事实和判断 |
| 20 | 破折号过密 | 破折号起手、单段连用 | 改逗号或分句 |

**对情酱skill的特别提醒**：第16条（硬凹网感）是这套风格最容易犯的反模式。口语词组、情绪标点、碎句都是情酱的合法工具，但堆密了就从"活人"变成"演活人"。判断标准是，删掉这个口语元素信息不变、语气也不缺，那它就是凹出来的。

## 误杀边界（不该改的，一律不动）

- **专业术语**：领域词（缓存层、异常分支、失效路径）不因字面像黑话就删。"根因"在事故复盘里是标准术语，保留
- **正式语域不强改**：官方公告保持公告腔，学术文体保留被动语态，产品文档保持条件表述。不跨语域强行统一成聊天体
- **信息密度优先**：带具体参数、数据、步骤的段落原样保留，不为节奏拆散证据链
- **嵌入式场景**：长文里嵌了一段技术复盘/引用公告，按该段自己的语域处理，不用全文标准碾过去
- **表演性与真实性的区分**：删的是套话和姿态，留的是带证据的真实表达。作者自己的口头禅、正常标点、个人习惯不是AI味
- **引语原文、产品名、命令**：默认保留，不进扫描范围

## 改写档位

| 档位 | 适用 | 允许的动作 |
|------|------|-----------|
| **minimal** | 文本基本自然 | 只删空总结、压过度语气、去"解释自己"的句子 |
| **standard** | 有明显AI腔或语域混搭 | 统一语域、改工程师腔、必要时并句或换主语 |
| **aggressive** | Tier 1密集、多类结构问题叠加 | 大幅重写，但先护住事实和术语 |

场景默认档位：聊天/短回复 minimal，状态同步 minimal-standard，技术文档 minimal（保守），公开发布文章 standard。

## 作用域（Scope）：删改权限三档

### structural

- **允许**：删整句空话、合并相邻句、重排段落
- **用于**：短文本、用户明确要求重写、AI味密度高的文本

### bounded（中文长文默认）

- **允许**：句子内部改写；纯空句列入**建议删除清单**，交用户确认
- **禁止**：直接删整句、合并句子、重排段落
- 一句话能进删除清单需同时满足三条：
  1. 删掉后信息不变
  2. 不是该处唯一的过渡
  3. 整句无事实、无功能（纯空话）

### in-place（用户说"别动太多""只微调"）

- **允许**：句内词语替换、删提示层、降调语气
- **禁止**：删整句、合并、重排
- 遇到整句空话，标注 **[空句，建议确认]**，不擅自软化或删除

### 回退检查（bounded / in-place 专用）

- 原文的每个信息点在输出里可追溯
- in-place 下成品字数低于原文 **85%** → 回头检查是不是删了整句（越权）
- 句数变化超过 **10%** → 回头检查是不是偷做了未授权的合并或重排

## 无源引用处理（三种模式）

| 模式 | 动作 | 用于 |
|------|------|------|
| **rewrite-safe** | 直接删掉"研究表明/专家认为"这类权威铺垫，保留句子的实质内容 | 从零创作（模式A/B/C）、聊天场景 |
| **audit-only** | 标注 **[缺来源，建议补充或删除]**，不擅自改写，必要时保留原句 | 改稿（模式D）、技术文档 |
| **rewrite-with-placeholder** | 写成"有研究认为…但此处未给出处"，绝不补虚构数据 | 仅用户明确要求保留原结构时 |

**改稿时的铁律**：不把无源引用改写成你编的个人立场。原稿写"专家认为将重塑行业"，你不能改成"说实话我也不确定"——那是替作者表态。

## 保真回读（Pass 1）：五项检查

改完先跑这一遍，逐项和原文/素材比对：

1. 保护片段有没有**漂移**（数字、名称、版本、日期逐个核对）
2. 信息有没有**丢失**（原文每个信息点可追溯）
3. 语域是否**统一**（没有半文半白、半口语半公文的混搭）
4. 术语有没有**失真**（不为口语化改坏专业表述）
5. 删改处有没有**生硬断裂**（删句之后上下文还接得上吗）

---

## 残余审计（Pass 2）：五项轻量修正

第一遍已保事实、但仍有轻微AI味时启用。只看五种残留：

1. **开场残留**：还有"结论先说""值得注意"式起手
2. **总结残留**：还有"总的来说""最终来看"式收束
3. **旁白残留**：还在解释"这说明了什么"
4. **空泛判断残留**：还有"意义重大""真正理解"式断言
5. **句长过匀**：整齐的抛光感（每句长度都差不多）

**允许**：删残留的开场/收尾、合并过匀的句子、拆过满的句子。
**禁止**：重写全文、补原文没有的事实、改术语/命令/报错。

扫完就停手。**不为了"像人"继续抛光到失真**——过度抛光和AI味一样假。

## 标注模式（annotation mode）

用户说"先标一下问题""只说问题，别改"时激活。**只输出问题清单，不产出改后成品**。

- 输出 1-5 个关键问题点，每点固定包含四项：
  1. **问题族**（开场套话 / 无源引用 / 工程师腔 / 语域混搭 / 结构反模式…）
  2. **触发点**（具体的词、结构或句子，原文引用）
  3. **建议动作**（删 / 换 / 补 / 保持）
  4. **是否建议改写**（是 / 否）
- 缺来源的句子可以只建议补来源，不强行给改写方案
- 落在误杀边界内的，直接写"是否建议改写：否"，说明保留理由
- 用户看完标注让你动手时，再按作用域规则进入正常改稿流程

## 正向目标（改完应该长什么样）

**五个正向标准**：

1. **具体动作优先**：用"谁做了什么、改了什么"替代"能力提升""价值释放"
2. **真主语真动作**：保留承载事实的主语和动词，减少"我们需要深入思考"式姿态层
3. **节奏自然不齐一**：允许长短不对称；重复如果承担转场、停顿、强调功能，可以保留
4. **允许普通句子**：不是每句都要像结论，普通承接句和事实句不需要包装成洞见
5. **语域统一不装人**：口语可以自然但不谄媚，专业可以严谨但不演洞见，观点可以鲜明但不喊口号

**三条反面清单**（"更像人"的三个陷阱）：

- 不强行口语化
- 不硬造个人voice
- 不靠金句、反问、碎句制造"人味"

**最终检验**：

1. 还在演"很会总结"吗
2. 关键判断落到动作、结果、例子、条件了吗
3. 句子被抹成同一种腔调了吗
4. 正式度被破坏了吗
5. 如果"更像人"需要补新事实，停手

## 快速决策树

```
用户丢来一段文字
  ├─ 说"改改/润色/去AI味/说人话" → 模式D，先定作用域再动手
  ├─ 说"先标问题/只说问题别改" → 标注模式，只出问题清单
  ├─ 给的是代码/命令/日志 → 不动
  ├─ 完整长文 + 没说改多少 → bounded + standard
  ├─ 短段落/短内容 → structural + minimal或standard
  ├─ 说"别动太多/只微调" → in-place
  └─ 说"按你的风格重写" → 这不是改稿，走模式A/B/C创作流程
```
